# syno-photosync

안드로이드 Synology Photos 앱으로 백업한 사진의 폴더 구성을 Synology Photos 의 **조건부 앨범**으로 자동 생성하는 스크립트입니다.
정해진 주기마다 실행되어 NAS 의 앨범 폴더마다 앨범을 만들고, 앨범 커버를 가장 늦게 촬영된 사진으로 맞춥니다.

- 대상: 지정한 DSM 계정(또는 그룹)의 **개인 공간** 사진 (공용 공간은 제외)
- 환경: Synology DSM 7.4 (Python 3.8), Synology Photos 1.9

## 설계

### 파일 구조

```
/photosync/
├── sync_album_folders.py        ← 스크립트 (진입점)
├── synology_photos_client.py    ← 포토 API 호출
├── target_user_resolver.py      ← 대상 계정·그룹 해석
├── folder_tree_collector.py     ← 폴더 트리 순회
├── album_folder_resolver.py     ← 앨범 폴더 판별 규칙
├── photosync.env                ← 환경변수
└── sync.log                     ← 실행 로그 (자동 생성)
```

### 환경변수

`photosync.env` 에 적습니다. 둘 중 하나 이상은 있어야 합니다. 값은 쉼표로 여러 개를 적을 수 있습니다.

| 변수 | 필수 | 설명 |
|---|---|---|
| `PHOTOS_USERS` | 선택 | 앨범을 만들 DSM 계정 |
| `PHOTOS_GROUPS` | 선택 | 앨범을 만들 DSM 그룹 (구성원 계정으로 풀어서 처리) |

비밀번호는 필요하지 않습니다. 로그인 대신 NAS 안에서 `synowebapi` 명령을 `runner=<계정>` 으로 실행해 그 계정의 개인 공간을 조회합니다.

### 동작

1. DSM 작업 스케줄러가 정해진 주기에 사용자 정의 스크립트를 **root 권한**으로 실행하고, 이 스크립트가 `python3 sync_album_folders.py` 를 실행해 출력을 `sync.log` 에 기록합니다.
2. `photosync.env` 에서 대상 계정과 그룹을 읽습니다. 그룹은 구성원 계정으로 풀어서 개별 계정과 합치고 중복은 한 번만 처리합니다.
   - 설정 파일이 없거나 계정과 그룹이 모두 비어 있으면 바로 종료합니다.
   - NAS 에 없는 계정, `-` 로 시작하는 이름, 조회에 실패한 그룹은 건너뛰고 로그에 오류를 남깁니다. 구성원이 없는 그룹은 경고만 남깁니다.
3. 계정마다 개인 공간(`Photos`)의 폴더 트리를 끝까지 순회해, 사진이 들어 있는 폴더에서 **앨범 폴더**와 앨범 이름을 정합니다. (규칙은 아래 표 참고)
4. 같은 이름의 앨범 폴더가 여러 경로에 있으면 하나의 앨범으로 합칩니다.
5. 계정의 기존 조건부 앨범과 비교합니다.
   - 폴더 조건이 같은 앨범이 이미 있으면 그대로 둡니다. (앨범 이름을 바꿔도 같은 앨범으로 봅니다)
   - 없으면 폴더 조건(폴더 소스)으로 조건부 앨범을 만듭니다. 사진이 0장이면 만들지 않습니다.
   - 같은 이름의 앨범이 있는데 폴더 조건이 다르면(같은 이름의 폴더가 나중에 늘거나 줄어든 경우) 폴더 조건을 현재 폴더 구성으로 바꿉니다. 폴더 조건이 없는 앨범(직접 만든 앨범)은 건드리지 않고 경고만 남깁니다.
6. 모든 앨범의 커버가 촬영 시각이 가장 늦은 사진이 아니면 바꿉니다.
7. 결과를 출력하고 종료합니다. 문제가 있었다면 오류 종료 코드로 끝나 작업 스케줄러가 알림을 보냅니다.

### 앨범 폴더 판별 규칙

안드로이드 앱은 `<업로드 경로>/<백업 폴더>/<년>/<월>/파일` 형태로 올립니다. 연/월 폴더(`YYYY/MM` 쌍)를 걷어낸 폴더가 앨범 폴더이고, 그 이름이 앨범 이름입니다. 앱의 연/월 폴더 자동 생성을 꺼도 동작합니다.

| NAS 경로 | 앨범 |
|---|---|
| `.../DCIM/Test/2026/10` | `Test` |
| `.../DCIM/Test` (연/월 폴더 없음) | `Test` |
| `.../DCIM/2026` (앨범 이름이 `2026`, 연/월 폴더 없음) | `2026` |
| `.../DCIM/2026/2026/10` (앨범 이름이 `2026`, 연/월 폴더 있음) | `2026` |
| `.../PhotoLibrary/2026/10` (포토 기본 타임라인 백업) | 업로드 루트라서 **제외** |
| `.../DCIM/Test`, `.../Pictures/Test` (이름은 같고 경로가 다름) | `Test` 하나로 **합침** |

`@eaDir` 같은 시스템 폴더는 무시합니다.

## 설치

### 1. 준비

- 안드로이드 Synology Photos 앱의 백업 설정에서 **백업할 폴더를 선택**합니다. 폴더 이름이 그대로 NAS 의 폴더가 되고 앨범 이름이 됩니다.
- 앨범을 만들 계정이 **개인 공간에 사진을 백업하는 DSM 계정**인지 확인합니다. 스크립트는 지정한 계정의 개인 공간만 봅니다.
- DSM 에서 **SSH 서비스를 활성화**합니다. (제어판 → 터미널 및 SNMP → 터미널 → SSH 서비스 활성화)
- 실패 알림 메일을 받으려면 제어판 → 알림에서 이메일 발송을 설정해 둡니다.

### 2. 파일 복사

스크립트를 실행할 경로를 정한 뒤 NAS 의 해당 경로에 파일을 복사합니다. 이 스크립트는 **root 권한**으로 실행되므로, 공유 폴더에 두면 SMB 등으로 다른 사용자가 파일을 고칠 수 있습니다. 4단계에서 권한을 확인하세요.

```bash
# 스크립트 실행 경로를 photosync 로 지정할 경우
/<볼륨>/<공유폴더>/photosync/
├── sync_album_folders.py
├── synology_photos_client.py
├── target_user_resolver.py
├── folder_tree_collector.py
├── album_folder_resolver.py
└── photosync.env.example
```

테스트 파일(`test_*.py`)은 복사하지 않아도 됩니다.

### 3. 환경변수 지정

NAS 에 **관리자 계정**으로 SSH 접속해 입력합니다.

```bash
# 스크립트 실행 경로를 photosync 로 지정할 경우
cd /<볼륨>/<공유폴더>/photosync
cp photosync.env.example photosync.env
```

`vi photosync.env` 등으로 파일을 열어 대상을 입력합니다. 계정, 그룹 중 필요한 것만 쓰면 되고, 쓰지 않는 줄은 `#` 으로 주석 처리합니다.

```bash
# 개별 계정과 그룹을 함께 지정할 경우
PHOTOS_USERS=user1,user2
PHOTOS_GROUPS=group1
```

### 4. 권한 확인

이 스크립트는 root 권한으로 실행되며, 설정 파일에 적힌 계정의 포토 공간을 조회·변경할 수 있습니다. 스크립트나 `photosync.env` 를 고칠 수 있는 사람은 root 권한을 얻는 것과 같으므로, **관리자 그룹 외의 사용자나 그룹이 이 폴더에 쓰기 권한을 갖지 않아야** 합니다.

**관리자 계정**으로 NAS 에 SSH 로 접속해 현재 권한을 확인합니다.

```bash
# 스크립트 실행 경로를 photosync 로 지정할 경우
cd /<볼륨>/<공유폴더>/photosync
sudo synoacltool -get .
```

출력에서 `everyone`, `users` 같은 항목이 `--x` 처럼 실행 권한만 갖고 있고, 관리자 그룹과 소유자 외에 `w` 가 포함된 권한(`rwxpdDaARWc` 등)이 없으면 됩니다.

- **사용자 홈 폴더(`homes`) 아래에 둔 경우**: DSM 이 기본으로 관리자 그룹에만 쓰기를 허용하고 다른 사용자에게는 폴더 진입만 허용하므로 대체로 충족합니다. 그래도 위 명령으로 확인하세요.
- **일반 공유 폴더에 둔 경우**: SMB 등으로 다른 사용자가 파일을 고칠 수 있으므로 아래처럼 지정합니다.

```bash
# 스크립트 실행 경로를 photosync 로 지정할 경우
cd /<볼륨>/<공유폴더>/photosync
sudo chown -R root:root .
sudo chmod -R go-w .
```

### 5. 드라이런으로 확인하기

NAS 에 **관리자 계정**으로 SSH 접속한 뒤, `--dry-run` 을 붙여 실행합니다. **붙이지 않으면 실제로 앨범을 만들고 바꿉니다.** 드라이런은 앨범을 만들거나 커버를 바꾸지 않고, 만들 앨범과 바꿀 커버를 로그로만 보여 줍니다.

```bash
sudo python3 -B /<볼륨>/<공유폴더>/photosync/sync_album_folders.py --dry-run
echo "exit code: $?"
```

계정마다 `===== 사용자 <계정> =====` 구분선이 나오고, 오류 없이 `exit code: 0` 이면 정상입니다.

| 로그 | 의미 |
|---|---|
| `앨범 폴더 N개를 찾았습니다` | 앨범으로 만들 수 있는 폴더(이름 기준) 개수 |
| `(드라이런) 폴더 [...]로 조건부 앨범을 만들 예정 (사진 N장)` | 실제로 실행할 때 새로 만들 앨범 |
| `(드라이런) 폴더 조건을 [...]에서 [...]로 바꿀 예정` | 실제로 실행할 때 폴더 조건을 갱신할 앨범 (같은 이름의 폴더가 늘거나 줄어든 경우) |
| `커버가 이미 최신 사진입니다` | 이미 맞춰진 앨범 |
| `(드라이런) 커버를 항목 N로 바꿀 예정` | 실제로 실행할 때 커버를 바꿀 앨범 |

문제가 있으면 출력된 메시지에서 원인을 확인합니다. 실제 앨범 생성은 6단계에서 등록한 작업이 실행될 때 이루어집니다.

### 6. 자동 실행 등록

DSM 제어판 → 작업 스케줄러 → 생성 → 예약된 작업 → 사용자 정의 스크립트

| 항목 | 값 |
|---|---|
| 사용자 | **root** |
| 스케줄 | 원하는 주기 (매시간 등) |
| 실행 명령 | 아래 스크립트 |

```bash
# <볼륨>, <공유폴더> 를 실제 볼륨·공유 폴더 이름으로 변경
cd /<볼륨>/<공유폴더>/photosync || exit 3
LOG=sync.log

echo "===== $(date '+%Y-%m-%d %H:%M:%S') =====" >> "$LOG"
python3 -B sync_album_folders.py >> "$LOG" 2>&1
status=$?
echo "exit code: $status" >> "$LOG"

# 로그가 무한히 커지지 않도록 마지막 2000줄만 남긴다
tail -n 2000 "$LOG" > "$LOG.tmp" && mv "$LOG.tmp" "$LOG"

exit $status
```

작업 설정의 **알림** 에서 "비정상 종료 시에만 실행 세부 정보 전송" 을 켜 두면, 종료 코드가 0 이 아닐 때 DSM 알림(메일)을 받을 수 있습니다.

등록한 작업을 선택하고 **실행** 을 누르면 스케줄을 기다리지 않고 바로 실행할 수 있습니다. 마지막의 `exit $status` 가 있어야 종료 코드가 스케줄러에 전달됩니다.

### 7. SSH 비활성화

모든 설정이 끝나면 보안을 위해 SSH 서비스를 다시 비활성화합니다. (제어판 → 터미널 및 SNMP → 터미널 → SSH 서비스 활성화 체크 해제)

## 알아둘 점

- **root 권한으로 실행됩니다.** `synowebapi` 는 root 로만 실행할 수 있습니다. DSM 의 root 계정으로는 로그인할 수 없지만, 작업 스케줄러에서는 사용자로 지정할 수 있습니다. 스크립트와 `photosync.env` 를 고칠 수 있는 사람은 root 권한을 얻는 것과 같으므로 4단계의 권한 확인을 지키세요.
- **포토 권한은 확인하지 않습니다.** `synowebapi` 는 계정의 응용 프로그램 권한(Synology Photos 허용 여부)을 검사하지 않고 그 계정의 개인 공간을 그대로 조회합니다. 처리할 계정은 `photosync.env` 에 적은 것으로만 통제됩니다.
- **폴더 조건은 NAS 의 폴더 구성을 따라갑니다.** 같은 이름의 폴더가 나중에 다른 경로에 생기면 기존 앨범의 폴더 조건에 추가되고, 폴더가 사라지면 조건에서 빠집니다. 포토에서 앨범의 폴더 조건을 직접 바꿔도 다음 실행에서 폴더 구성대로 되돌려집니다.
- **앨범 이름을 바꾼 뒤에는 새 앨범이 생길 수 있습니다.** 앨범 이름을 바꿔도 폴더 조건이 같으면 같은 앨범으로 봅니다. 그런데 이름을 바꾼 상태에서 같은 이름의 폴더가 새로 생기면 폴더 조건이 달라져서, 원래 이름으로 새 앨범이 만들어집니다.
- **앨범은 지우지 않습니다.** 같은 이름의 폴더가 여러 개일 때 일부가 사라지면 폴더 조건에서만 빠지고, 앨범의 폴더가 모두 사라져도 이미 만들어진 앨범은 그대로 남습니다.
- **직접 만든 앨범은 건드리지 않습니다.** 폴더 조건이 없는 조건부 앨범과 이름이 같은 폴더가 있으면 그 앨범을 바꾸지 않고 경고(`같은 이름의 앨범이 있지만 폴더 조건이 없는 앨범이라 건드리지 않습니다`)만 남깁니다.
- **사진이 없는 폴더는 앨범으로 만들지 않습니다.** 사진이 올라오고 포토가 인덱싱을 마친 뒤의 다음 실행에서 만들어집니다.
- **제외할 폴더를 지정하는 기능은 없습니다.** 백업할 폴더를 앱에서 직접 고르므로, 앱에서 백업하지 않은 폴더는 앨범이 만들어지지 않습니다. 업로드 루트(`Photos` 루트, `PhotoLibrary`)의 기본 타임라인 백업만 자동으로 제외됩니다.
- **연/월 폴더와 구별할 수 없는 이름은 오판할 수 있습니다.** 연/월 폴더를 끈 상태에서 앨범 폴더 이름이 `10`이고 부모 폴더 이름이 `2026` 이면 연/월 폴더로 보고 앨범으로 만들지 않습니다.
- **비공식 API 를 사용합니다.** 포토 웹 API 는 공개되어 있지 않아서 DSM 이나 Synology Photos 를 업데이트하면 동작이 바뀔 수 있습니다. 업데이트 후에는 드라이런으로 한 번 확인하세요.
- **공용 공간은 대상이 아닙니다.** 개인 공간(`SYNO.Foto.*`)의 폴더만 처리합니다.
